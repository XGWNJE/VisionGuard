# 来源抽屉与设置抽屉分区清点

负责：任务 15 的方案——Android 视觉推理节点「来源抽屉」与「全局设置抽屉」的分页、分区、去重与文案清单。不负责：实现事实（落地后见 [Android 视觉推理节点](31-Android视觉推理节点.md)）、验证证据（见 [验证记录](90-验证记录.md)）与任务状态（见 [任务清单](06-任务清单.md)）。更新时机：方案调整时；落地后把事实并入 31、删除本文。

范围：只动 Android 视觉推理节点。Windows 视觉推理节点（来源检查区与全局设置页）和 Web 控制台没有「抽屉」这套结构，不在本轮；需要时另立任务。

## 背景

- 三页抽屉（来源 / 检测参数 / 遮罩）每页都超出抽屉内容区。检测参数页把机器控件、模型插片与检测目标塞在一页，模型与检测目标被挤到折叠线以下（`.local/console-preview/r1-drawer-params.png`）；遮罩页画布占满抽屉宽度，遮罩列表被挤到折叠线以下（`.local/console-preview/r1-drawer-mask.png`）；来源页四个区块合计约 620dp。
- 设置抽屉里有多处与来源抽屉、来源列表重复：推理状态（推理后端 / 单帧耗时）、模型概览（四行档位清单）、遮罩合计、运行来源、远程来源。
- 界面从未显示 `RuntimeUiState.alertCount` 与 `lastAlertAtMs`（应用级累计报警与最后一次报警），状态有家难归。

## 高度预算（一页装得下的判据）

参考设备 26048RP6AC：1880×3008、密度 472 → 横屏 1019×637dp。

- 每页正文可用高度 = 637 − 抽屉头 77 − 页脚 76 − 内容内衬 40 − 拨档 48 − 间隔 12 ≈ **384dp**。
- 设置抽屉宽屏是「左栏分区导航 + 右栏滚动内容」，右栏内容区高度与上同；分区按内容长度设计，不要求每条都一屏。
- 现有三页分别约 620 / 990 / 700dp，都超。

## 来源抽屉：拆成六页

| 页（2 字标签） | 正文 | 估算高度 |
|---|---|---|
| 运行 | 01 运行状态：状态灯 + 两列 8 格信息网格 + 远程来源时一行「推流来源」 | ~344 |
| 来源 | 01 来源名称（输入 + 保存 / 还原 + n/64）、02 镜头（仅本机相机）、03 维护（删除来源 + 二次确认） | ~338 |
| 参数 | 只读 / 可编辑灯条 +（运行中）只读提示，或（有阻塞）保存条件行 + 01 采样频率、02 置信度、03 报警冷却；宽屏三列逐段等高、窄屏纵排 | ~316（含条件行 ~348） |
| 模型 | 01 模型插槽：4 档两列插片（下载 / 删除 / 选中唯一入口）+ 无 GPU 降档提示 + 换模型复核勾选 + 未下载红字 | ~300 |
| 目标 | 01 检测目标：搜索 → 已选 chip → 排片，底部一行计数与「全部 80 类」 | ~348；展开全部时收起已选行、池高 264→196dp 内滚 → ~352 |
| 遮罩 | 灯条 + 提示条 + 工具行；宽屏两栏：左画布｜右遮罩列表 + 删除选中 / 清空全部 + 错误行 | ~361 |

- 页脚按页：运行 / 来源＝关闭；参数 / 模型 / 目标＝还原 / 取消 / 保存参数（同一份草稿、同一套 `canSave` 校验）；遮罩＝还原当前值 / 取消 / 保存遮罩。
- 拨档保持放在滚动内容里：参考设备上每页不需要滚动，拨档始终可见；加固定槽位要多占 72dp，不做。
- 参数草稿跨「参数 / 模型 / 目标」三页共享；新增「保存条件」行，任一参数页都能看到阻塞原因（模型未下载 / 未复核检测目标 / 至少选一个检测目标 / 检测目标超出上限）；运行中只给只读提示，不叠加条件行。
- 来源行方键打开**运行**页；设置里的「打开模型页」打开**模型**页。
- 为什么是六页：运行 + 来源 634、模型 + 目标 598、参数 + 模型 550，都超 384dp；拆页依据是高度，不是语义分类，所以模型与目标必须各占一页。

### 遮罩页宽屏两栏

`MaskPage` 外套 `BoxWithConstraints`：`maxWidth ≥ 660dp` 时工具行下方用 `Row`——左 `weight(1.6f)` 放画布（等比、26dp 内衬、四角把手、归一化坐标全部不变），右 `weight(1f)` 放「遮罩列表」+ 列表（`heightIn(max = 130.dp)` 内部滚动）+ 删除选中 / 清空全部 + 错误行；窄屏维持今天的上下堆叠顺序。无画面说明留在左栏画布下方。

**清点发现（无家可归的状态）**：`RuntimeUiState.alertCount` 与 `lastAlertAtMs` 由运行时维护、界面从未显示（只有每来源的「最后报警」）。归位到「连接」的报警回执语义里，显示为一行「本次运行累计 n 次 · 待回执 m 条 · 最后 <本地时间>」；实现时先核对确实是进程内累计、不跨启动。

### 分区结果与残留滚动

- **账号**：账号名 / 服务地址 / 设备身份 + 设备名称编辑 + 修改密码 + 退出登录（约 600dp，宽屏仍会滚动——滚动的是两段表单，不是数据混排）。
- **连接**：控制通道 / 媒体通道 / 远程收帧 / 报警回执 / 来源上限 / 服务时钟（约 280dp）。
- **模型**：本机 GPU 加速 / 已下载档位 + 一句 hint + 打开模型页（约 200dp）。
- **外观**：主题模式 + 色板 + hint（约 200dp）。
- **后台**：前台服务 / 通知权限 / 相机权限与采集 + 打开系统应用设置 + hint（约 260dp）。
- **维护**：版本与更新 / 临时缓存 / 崩溃与退出记录 / 开发项（崩溃列表与报告天生会滚动）。
- 六分区标签都是 2 字：窄屏拨档六档每档约 53dp（≥48dp 触点），宽屏左栏 6×48dp。

### 文案精简（before → after）

1. 后台 hint：「有来源在运行时保持前台服务，界面退到后台或锁屏后推理继续；运行意图按来源保存，进程被系统回收后服务按意图恢复。」→「有来源运行时保持前台服务，退后台或锁屏继续推理；运行意图按来源保存，进程被回收后按意图恢复。」
2. 权限 hint（label 已写「本机授权不可远程绕过」）：「相机与通知权限只能由本机用户在系统里授权；控制台不能远程绕过，应用也不会自行修改锁屏或唤醒设置。」→「相机与通知权限只能由本机用户在系统里授权；本应用不修改锁屏与唤醒设置。」
3. 模型 hint（两条合一）→「档位的下载、删除与选择在「模型」页：未下载不可选，使用中不可删。CPU 档走 ONNX Runtime CPU，GPU 档走 LiteRT GPU，用不了时回落同尺寸 CPU 档。」
4. 外观 hint →「色板与统一 UI 规范同源；只有「跟随系统」响应系统深浅色。」
5. 版本 hint →「升级只安装官方稳定版，不改动本机配置与账号数据。」
6. 缓存 hint →「只清截图、诊断导出与安装包暂存；模型、账号、配置与回滚资料不动。」；确认文案 →「确认清理过期临时缓存？模型、账号与配置不会被清理。」
7. 崩溃 hint →「未捕获异常由本机记录；native 崩溃、ANR 与内存回收从系统退出原因读取。」
8. 退出确认 →「退出会停止全部来源并清除本机会话；本机参数与遮罩保留。」
9. 账号区段尾注「本机保存」删除；会话尾注「退出会停止全部来源」保留。

## 边界、失败模式与不做

- 运行中：参数三页与遮罩页只读，保存禁用，只给只读原因。
- 无 GPU：模型页保留「已换同尺寸 CPU 档」提示与复核勾选；设置「模型」保留 GPU 可用性一行。
- 远程来源：来源页无镜头区块，多一段「03 远程绑定」（说明该绑定按发布端生效 + 「解除绑定」键，见[Android 视觉推理节点](31-Android视觉推理节点.md)）；运行页多一行「推流来源」。
- 无画面：遮罩页显示说明、保存禁用（现状）。
- 窄屏 <660dp：机器三块纵排、遮罩页上下堆叠、页内滚动照旧；目标五列在手机上偏窄是既有问题，本轮不改。
- 抽屉打开期间来源被移除：沿用现有 `LaunchedEffect` 收起。
- 设置抽屉无来源时：「打开模型页」仍禁用。
- 不改 `DetectionParams`、遮罩模型、运行时、协议与持久化；不动 `VERSION`。
- 不做：Windows 节点与 Web 控制台清点、未保存草稿关闭确认（另立任务）、给抽屉加固定拨档槽位、给来源「运行」页加启停键（逐来源启停归来源行）。
- push / 合 `main` / 打 tag / 删分支由 owner 决定；分支先合入主线才能删除。
