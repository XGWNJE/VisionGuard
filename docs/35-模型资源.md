# Model Assets

负责：Model Assets。不负责：其他模块事实、任务状态或重复验证记录。更新时机：该主题源码或约束变化时；历史发行说明只纠正事实，不随当前版本改写。


模型文件（.onnx）不入版本控制，不随发行包分发。客户端首次启动或切换模型时从统一服务按需下载，本地缓存复用。

## 当前模型集合

### 视觉推理节点 legacy 档（Win7 SP1 x64，YOLOv5）

legacy 档的 ONNX Runtime 原生库是 1.1.0，算子覆盖不足以支撑 YOLO26，因此固定使用 YOLOv5 系列：

- `yolov5nu_320.onnx`
- `yolov5nu_640.onnx`
- `yolov5su_320.onnx`
- `yolov5su_640.onnx`
- `yolov5mu_320.onnx`
- `yolov5mu_640.onnx`

### 视觉推理节点 modern 档（Win10/11，YOLO26）

- `yolo26n_320.onnx`
- `yolo26n_640.onnx`
- `yolo26s_320.onnx`
- `yolo26s_640.onnx`
- `yolo26m_320.onnx`
- `yolo26m_640.onnx`

### 视觉推理节点 Android 档（YOLO26）

Android 推理节点使用与 Windows modern 档同一套 YOLO26 本体，**可选键共 12 项**：6 个基名的 FP32 本体（`yolo26{n,s,m}_{320,640}.onnx`）与 6 个量化版（同键加 `_int8` 后缀）。另有 1 个 GPU 加速产物 `yolo26m_640_gpu.tflite`。模型在设备上加载并执行，不随安装包分发，按需从统一服务下载。移动端不使用 Win7 legacy 的 YOLOv5 模型，解析器也不再保留 YOLOv5 锚点分支（锚点档只服务 GPU 的截断图，语义见[推理框架](32-推理框架与模型优化.md#验收口径)）。

服务端已投放这 13 个文件（12 个 `.onnx` + 1 个 `_gpu.tflite`）。投放用 `scripts/deploy-int8-models.ps1 -Kind Quantized|Gpu`，带 ONNX Runtime / LiteRT 真加载校验与 sha256 比对。

`scripts/prepare-android-nnapi-model.py` 是 NNAPI 路线的遗留脚本：NNAPI 已放弃（真机负优化），本脚本不再参与发布准备，仅作为历史工具保留。

## 模型按需下载

### 统一服务端点

- 路由：`/models/{filename}`，express.static，无需鉴权；`.onnx` 与 `_gpu.tflite` 都走同一目录
- 源文件：`server/data/models/`（`.onnx` 由 `scripts/publish-release.ps1` 从 `detector\windows-wpf\Assets\` 收集；GPU 与量化产物用 `scripts/deploy-int8-models.ps1` 投放）

### 构建机的模型就位

模型 .onnx 不入版本控制，`detector\windows-wpf\Assets\` 在干净检出时是空的，而服务器上的模型完全由发布脚本从这个目录收集。因此**发布前必须让两个档位的 12 个模型都在该目录里**（约 530 MB）：导出可用 `scripts/export-yolov5-models.py`（YOLOv5）与 YOLO26 的导出流程，或直接从现网 `<server>/models/<键>.onnx` 取回。

`scripts/publish-release.ps1` 的预检会逐项校验这 12 个模型存在且不小于 1 MB，缺任一项直接中止发布——缺模型不会让构建失败，只会让下发出去的机器下载不到模型。

### 客户端本地缓存

| 端/档位 | 路径 | 管理类 |
|---|---|---|
| 视觉推理节点（legacy 与 modern 两档共用同一缓存目录，清单按档位切换） | `%APPDATA%\VisionGuard\models\{modelKey}.onnx` | `Utils\ModelManager.cs` |
| Android 推理节点（应用私有目录；GPU 产物落成 `{键}_gpu.tflite`） | `files/models/{文件名}` | `model/ModelStore.kt` |

### 首次安装 / 旧版升级

启动时自动将旧路径（exe 同目录 `Assets\`）的模型迁移到 `%APPDATA%` 缓存目录，避免重复下载；这只是升级兼容路径，不是新的模型分发入口。

### 下载行为

- 默认模型选中后自动下载（StartMonitor 前检测，缺失则下载 + 进度条）
- 设置页模型选择处可手动下载任意模型，实时显示百分比
- Android 推理节点按需下载本端清单内的模型（12 项，另加 `yolo26m_640` 的 GPU 产物）：先写 `.tmp`，校验声明内容长度并确认不小于 1 MiB 后才替换正式文件；长度不符或过短时删除临时文件并报可读原因。设置里每个模型标出它跑在哪（`GPU` / `CPU` / `CPU · INT8`）

## 输出格式

- 视觉推理节点 legacy 档 YOLOv5：`[1,84,N]`
- 视觉推理节点 modern 档与 Android 推理节点 YOLO26：`[1,300,6]`

## COCO 映射真相源

- 视觉推理节点：`detector/windows-wpf/Data/CocoClassMap.cs`
- Android 推理节点：`detector/android-inference/app/src/main/java/com/xgwnje/visionguard/inference/detect/CocoClassMap.kt`（与 Windows 源码对齐的独立静态表）

## 统一目标子集

当前多端对齐的 6 类监控目标：

- `person`
- `bicycle`
- `car`
- `motorcycle`
- `bus`
- `truck`

## 维护规则

- 模型文件不入 git 版本控制（`.gitignore` 排除 Windows `Assets/*.onnx`；Android 应用不设模型 assets 目录，Android 推理节点下载到应用私有缓存）
- 视觉推理节点项目文件从构建项中排除 `Assets/`；目录仍可保存发布所需模型，正式压缩阶段也排除该目录。
- 类目中英文映射引用源码静态表，不手动复制文档
- 导出脚本、模型文件名、输入尺寸只在源码已存在时写入说明
