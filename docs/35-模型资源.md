# Model Assets

负责：Model Assets。不负责：其他模块事实、任务状态或重复验证记录。更新时机：该主题源码或约束变化时；历史发行说明只纠正事实，不随当前版本改写。


模型文件（.onnx）不入版本控制，不随发行包分发。客户端首次启动或切换模型时从统一服务按需下载，本地缓存复用。

## 当前模型集合

三端清单自 2026-10-12 起收敛为最小可用集合，代码、产物与部署均已落地（投放与下架证据见[验证记录](90-验证记录.md#服务端模型收敛投放2026-10-12发布动作)）；下面写的是收敛后的清单。

### 视觉推理节点 legacy 档（Win7 SP1 x64，YOLOv5）

legacy 档的 ONNX Runtime 原生库是 1.1.0，算子覆盖不足以支撑 YOLO26，因此固定使用 YOLOv5 系列。低端机长期实测后只留 320 两档：

- `yolov5su_320.onnx`
- `yolov5mu_320.onnx`

### 视觉推理节点 modern 档（Win10/11，YOLO26）

固定 320 / 640 两档，走 FP32 + DirectML：

- `yolo26m_320.onnx`
- `yolo26m_640.onnx`

### 视觉推理节点 Android 档（YOLO26）

Android 用户档位只有 M320 / M640（`yolo26m_320` / `yolo26m_640`）；每档同时下载 `<键>_int8.onnx` 与 `<键>_gpu.tflite`，完整后才可选择。兼容时优先 LiteRT GPU，否则回落同尺寸 ONNX INT8 并报告原因。模型不随包分发，按需从当前登录服务下载；不提供后端优先级设置。

服务端按此清单收敛为 8 个文件：4 个本体（legacy 2 + modern 2）、2 个 Android 量化版、2 个 GPU 产物；`yolo26{n,s}_{320,640}` 与其量化版、旧 v5 四档共 12 个文件（约 267 MiB）下架。投放用 `scripts/deploy-int8-models.ps1 -Kind Quantized|Gpu`，带 ONNX Runtime / LiteRT 真加载校验与 sha256 比对。

`scripts/prepare-android-nnapi-model.py` 是 NNAPI 路线的遗留脚本：NNAPI 已放弃（真机负优化），本脚本不再参与发布准备，仅作为历史工具保留。

## 模型按需下载

### 统一服务端点

- 路由：`/models/{filename}`，express.static，无需鉴权；`.onnx` 与 `_gpu.tflite` 都走同一目录
- 源文件：`server/data/models/`（`.onnx` 由 `scripts/publish-release.ps1` 从 `detector\windows-wpf\Assets\` 收集；GPU 与量化产物用 `scripts/deploy-int8-models.ps1` 投放）

### 构建机的模型就位

模型 .onnx 不入版本控制，`detector\windows-wpf\Assets\` 在干净检出时是空的，而服务器上的模型完全由发布脚本从这个目录收集。因此**发布前必须让两个档位的 4 个模型都在该目录里**（约 287 MiB）：导出可用 `scripts/export-yolov5-models.py`（YOLOv5）与 YOLO26 的导出流程，或直接从现网 `<server>/models/<键>.onnx` 取回。

`scripts/publish-release.ps1` 的预检会逐项校验这 4 个模型存在且不小于 1 MB，缺任一项直接中止发布——缺模型不会让构建失败，只会让下发出去的机器下载不到模型。

### 客户端本地缓存

| 端/档位 | 路径 | 管理类 |
|---|---|---|
| 视觉推理节点（legacy 与 modern 两档共用同一缓存目录，清单按档位切换） | `%APPDATA%\VisionGuard\models\{modelKey}.onnx` | `Utils\ModelManager.cs` |
| Android 推理节点（应用私有目录；GPU 产物落成 `{键}_gpu.tflite`） | `files/models/{文件名}` | `model/ModelStore.kt` |

### 首次安装 / 旧版升级

启动时自动将旧路径（exe 同目录 `Assets\`）的模型迁移到 `%APPDATA%` 缓存目录，避免重复下载；这只是升级兼容路径，不是新的模型分发入口。

### 下载行为

- Windows 默认模型选中后自动下载（StartMonitor 前检测，缺失则下载 + 进度条）
- Windows 设置页可手动下载支持的模型，实时显示百分比
- Android 模型下载、删除与选择以 M320 / M640 为单位；无完整模型时不默认选中，两个文件都校验成功后才可选。先写 `.tmp`，校验声明长度与最小 1 MiB 后替换，删除时同时移除两种产物并清除已停止来源的对应选择；清单外旧文件由本机盘点清理。

## 输出格式

- 视觉推理节点 legacy 档 YOLOv5：`[1,84,N]`
- 视觉推理节点 modern 档与 Android 推理节点 CPU 档 YOLO26：`[1,300,6]`（图内 NMS）
- Android 推理节点 GPU 档：截断图 `[1,84,N]` 锚点，NMS 在端侧解析

## COCO 映射真相源

- 视觉推理节点：`detector/windows-wpf/Data/CocoClassMap.cs`
- Android 推理节点：`detector/android-inference/app/src/main/java/com/xgwnje/visionguard/inference/detect/CocoClassMap.kt`（与 Windows 源码对齐的独立静态表）

## 维护规则

- 模型文件不入 git 版本控制（`.gitignore` 排除 Windows `Assets/*.onnx`；Android 应用不设模型 assets 目录，Android 推理节点下载到应用私有缓存）
- 视觉推理节点项目文件从构建项中排除 `Assets/`；目录仍可保存发布所需模型，正式压缩阶段也排除该目录。
- 类目中英文映射引用源码静态表，不手动复制文档
- 导出脚本、模型文件名、输入尺寸只在源码已存在时写入说明
