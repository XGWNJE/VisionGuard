# VisionGuard v0.7.4

负责：本版发行范围和安装说明。不负责：完整验证报告。更新时机：本版发行内容变化时。

## 本版内容

- **修复通知节点连不上闸门实例的问题**：通知节点的控制通道一直声明 `0.7.1`——`BuildConfig.VERSION_NAME` 是 Java 静态常量，会被 Kotlin 在编译期内联成字面量，而承载它的 class 在 0.7.2 / 0.7.3 的增量构建里被直接复用，于是 0.7.1 起的三个发行包都声明旧版本（manifest 与设置页显示的版本仍是对的，所以肉眼看不出来）。表现是：登录成功（HTTP 走安装包版本，能过闸门），随后控制通道被闸门静默切断（WS 4001），App 判定「登录已失效」并清会话回到登录页，且没有任何错误提示。本版把通知节点的版本改成运行期读取，并重建发行包。
- **新增「打包产物协议版本」硬检查**：`scripts/check-apk-protocol-version.js` 解析 APK 内 `classes*.dex` 的字符串表，断言包内出现文件名里的版本号；发布 preflight 在写发行元数据前对每个 Android 产物强制跑一遍，检查脚本自身的测试进两个 CI 工作流。`scripts/check-protocol-declarations.js` 同时收紧为「Android 三端的版本必须运行期读取」，写回 `const val` 或写死字面量都会被拦下。
- **升级提醒（同 0.7.3 的行为）**：协议版本随本版升到 `0.7.4`，服务端升级后**没升级的端会被切断并从节点目录与推流视图消失**，按本版协议重新声明（升级后重新登录 / 重连）即恢复。这是预期行为，不是故障。
- 发布 Windows 视觉推理节点、Android 相机推流节点、通知节点、视觉推理节点，以及统一服务 / Web。

## 安装与检查

更新各客户端并刷新[线上控制台](https://visionguard.xgwnje.cn/console/)。各端「关于 / 版本」当前应为 0.7.4。

- **Windows 视觉推理节点**：仍是一个统一包，启动器在本机选择内部推理运行时。
- **Android 视觉推理节点**：可在应用内「设置 → 维护 → 检查更新」升级。
- **Android 相机推流节点、通知节点**：可在应用内检查 GitHub 稳定版并交系统安装器确认，也可手动安装对应发行包。
- **升级顺序**：先升级服务端（发布流程自动部署），再升级四个平台的客户端；窗口期内未升级的端会被切断并从节点目录隐藏，属预期。

构建、发行附件与真机证据见[验证记录](../90-验证记录.md)。
