# VisionGuard v0.7.5

负责：本版发行范围和安装说明。不负责：完整验证报告。更新时机：本版发行内容变化时。

## 本版内容

- **修复发行包一选 GPU 档就闪退**：安卓视觉推理节点在发行（R8 压缩）包里选 GPU 档必闪退，CPU 档推理正常，与本机相机还是接收推流无关。原因是 LiteRT 的原生桥按硬编码类名查找 Java 类型（`TensorType$ElementType`、`TensorType$Layout`、`TensorBufferRequirements`、`LiteRtException`），R8 把它们删掉或改名后，原生层走的不是 Java 异常而是致命 CHECK，进程直接 abort，Kotlin 侧的 `runCatching` 抓不住；生产链路里 LiteRT 只用于 GPU 档（CPU 档走 ONNX Runtime），所以只有 GPU 档中招。本版在 `app/proguard-rules.pro` 里整体保留 `com.google.ai.edge.litert.**`，发行包 `classes.dex` 已复核这些类回归。
- **顺带修好 GPU 编不过时的回落**：缺失的 `LiteRtException` 同时也是原生层报错路径要用的类，所以此前在 GPU 编译失败的设备上不是「回落同尺寸 CPU 档」而是闪退；保住这些类之后回落路径恢复正常。
- **影响范围说明**：0.6.12 起的发行包都带这个缺陷，但此前所有 GPU 成功读数都来自 debug / 测量包（测量入口受 `BuildConfig.DEBUG` 门控），发行包从未跑过 GPU 档，所以一直没被触发。
- **升级提醒（同 0.7.3 起的行为）**：协议版本随本版升到 `0.7.5`，服务端升级后**没升级的端会被切断并从节点目录与推流视图消失**，按本版协议重新声明（升级后重新登录 / 重连）即恢复。这是预期行为，不是故障。
- 发布 Windows 视觉推理节点、Android 相机推流节点、通知节点、视觉推理节点，以及统一服务 / Web。

## 安装与检查

更新各客户端并刷新[线上控制台](https://visionguard.xgwnje.cn/console/)。各端「关于 / 版本」当前应为 0.7.5。

- **Windows 视觉推理节点**：仍是一个统一包，启动器在本机选择内部推理运行时。
- **Android 视觉推理节点**：可在应用内「设置 → 维护 → 检查更新」升级；升级后在来源参数抽屉里选 GPU 档（`YOLO26M · 320 GPU` / `640 GPU`）应能正常推理。
- **Android 相机推流节点、通知节点**：可在应用内检查 GitHub 稳定版并交系统安装器确认，也可手动安装对应发行包。
- **升级顺序**：先升级服务端（发布流程自动部署），再升级四个平台的客户端；窗口期内未升级的端会被切断并从节点目录隐藏，属预期。

构建、发行附件与真机证据见[验证记录](../90-验证记录.md)。
