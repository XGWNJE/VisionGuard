# 视觉节点

负责：视觉节点。不负责：其他模块事实、任务状态或重复验证记录。更新时机：该主题源码或约束变化时；历史发行说明只纠正事实，不随当前版本改写。


本文维护当前实现和必要约束。组件地图见[项目概览](10-当前架构.md)，命令见[运维](60-构建验证与发布.md)，本轮验证和未覆盖项见[验证报告](90-验证记录.md)。

## 入口与运行时

| 入口 | 当前职责 |
|---|---|
| `detector/windows-launcher/` | 视觉节点统一入口；选择内部运行时；整包下载、大小/SHA256 校验、安全解压、目录切换和失败回滚 |
| `detector/windows-wpf/` | net472 WPF x64，同一份界面与检测链，按 `OrtProfile` 构建两个内部推理档位 |
| `detector/windows-resident/` | 视觉节点的内部后台驻留程序；net472 x64 当前用户进程，承接生命周期远控 |

| 档位 | 系统 | 推理组合 | 输出契约 |
|---|---|---|---|
| legacy | Win7 SP1 x64 | 托管 ONNX Runtime 1.2.0 + 原生 1.1.0，CPU，YOLOv5 | `[1,84,N]`，N=2100/8400；逐类 NMS 后取前 5 |
| modern | Win10/11 | 托管/原生 ONNX Runtime 1.19.0，DirectML/CPU，YOLO26 | `[1,300,6]`，模型内含 NMS；阈值/类别过滤后取前 5 |

档位、依赖与原生库布局以 `detector/windows-shared/NativeLibraries.props` 为准。原生库放在 `native/<档位>/`，应用根目录不能残留 ONNX/DirectML DLL；启动时绝对路径预加载并核验实际模块路径，失败明确报错。模型清单与缓存见[模型资源](35-模型资源.md)。Win7 前提是 .NET Framework 4.7.2 与 TLS 1.2 系统支持，构建不能替代实机验收。

后台更新检查失败只记录日志，不阻断主窗口启动；手动检查以更新提示显示错误。缺少下载地址或 SHA256 的元数据仍拒绝使用，不启动下载。

更新器直接查询 GitHub 稳定发行，不发送账号凭证。按数值版本、发布时间和 `VisionGuard-WPF-v版本.zip` 精确选择，跳过只更新其他客户端的发行；当前版本发行的发布时间作为历史边界，未发布开发版本仅在同一主版本内检查。大小与 SHA256 必须完整；下载可取消，失败移除本次暂存文件。检查／应用使用安装目录对应的互斥锁。完整包、解压范围与新启动器文件版本先校验，复制至独立准备目录并复验后才关闭旧进程和切换目录；准备失败不关闭旧程序。新 WPF 主窗口首次呈现才写启动确认，超时或切换失败恢复旧目录并重启；回滚失败保留可恢复的目录位置并报错。新版本启动确认不等于全部功能验收。

控制、远程媒体和后台驻留共用 `MinimalWebSocketClient`。WSS 在 HTTP 升级请求和业务认证之前由系统验证证书信任链、有效期及目标域名；失败、取消或握手超时均关闭 TLS/TCP。保留 TLS 1.2 与 net472 的 Windows 7 兼容，旧系统必须有有效根证书，不能跳过验证。此处不强制在线吊销查询，避免 Win7 吊销服务不可达阻断必要连接。

## 检测与来源

`Capture → MaskApply → Preprocess → ONNX Inference → Parse → AlertDecision → Push`

- 采集窗口客户区或屏幕选区；目标和窗口子区域的宽高都须严格大于 100 像素。窗口身份使用标题、类名和进程名，非唯一候选不自动重绑。
- 远程镜头通过账号媒体连接进入 `RemoteStream` 来源；服务确定账号与目标节点，自动创建稳定来源卡片，复用遮罩、模型、检测参数、截图与报警。只处理新帧，本地单调计时限制帧龄；主动停流与异常断流分别显示。
- 遮罩是帧内 `[0,1]` 相对坐标；推理前涂黑并影响报警截图。采集目标更换时整体重置目标与遮罩。
- 预处理等比缩放、黑边补齐；解析去除补边并映射回原始帧。PerMonitorV2 处理界面缩放，采集坐标按当次客户区重绘帧计算。
- 来源列表只保留已完成采集配置或已绑定远程镜头的来源，可以为空；按统一服务下发上限增删，运行中先停止才能删除。手动添加先配置临时草稿，取消或失败不加入列表、不持久化草稿；最后一个本地来源也可删除。`sourceId` 稳定，`sourceName` 可改；既有 `default` / `signal-N` 身份保留。
- 每路独立采集、模型、配置、推理、冷却和错误状态；故障只影响本路。多路 CPU 允许运行，不自动减路、降帧或换模型。
- 运行中拒绝改配置；主检查区展示参数摘要，独立编辑窗口统一还原、取消与保存整组参数。草稿不提前写盘，保存失败整组回退并保留草稿；外部配置变化时要求先还原当前值。采集目标与名称沿用自动保存，500ms 防抖。模型、类别、阈值、频率与冷却在下一次启动生效；冷却范围 1–300 秒，置信度 10–95% 整数、采样 1–5 FPS 整数。已知模型使用实际 COCO 80 标签，中文搜索至少一项；未知或未下载模型明确不可用。心跳完整回传模型标签和目标列表，不截断。
- 有完整采集配置才可启动；状态统一为“检测中”与“未就绪”。心跳同时上报运行意图 `monitoringExpected` 与最后成功处理时间 `lastProgressAt`；主动停止清除运行意图。心跳只上报已绑定来源，暂时失联的绑定来源保留并报故障，空槽位不报。
- 实测 FPS 低于目标 80% 连续 30 秒时提示性能不足，提醒冷却 10 分钟；故障与性能不足分别表达，FPS 只统计成功帧。
- 带 `targetSourceId` 的控制只作用于该来源；设备级 `pause` / `resume` 作用于全部来源。远控统一由主 ViewModel 路由，每条命令只执行一次；启停和参数保护按协调器实际运行状态判断，不依赖异步界面状态；重复启动不会重建运行中的来源，启动失败返回失败回执。
- 停止只等待实际正在处理的帧，空闲来源立即停止；帧在两秒内未结束时返回可重试的失败，不释放仍在使用的推理引擎。
- 报警先写按服务、账号和设备分区的持久 outbox，收到统一服务持久化 `alert-ack` 才移除，再异步发送截图；实时期限为事件发生后 30 秒，过期队列项清除且不补传；损坏队列隔离并记录原因。

## 界面与配置

- 主窗口、设置、工具窗口、应用提示与托盘采用[统一 UI 规范](70-UI设计规范.md)。WPF 提供跟随系统／浅色／深色并保存选择，高对比度优先系统调色板；采集画面与编辑覆盖层使用专用颜色，不改变选区及遮罩语义。
- 主界面只保留左侧主预览、中间纵向来源预览列表、右侧来源检查三个分区，移除应用内顶栏、预览勾选及底部来源条。点击来源同步主画面与检查对象。全部有效来源提供预览卡片；列表滚动与虚拟化只减少不可见卡片的位图刷新，不停止采集、推理或报警。已配置来源临时失联保留配置与卡片，显示真实状态。
- 默认 1420×800 DIP、最小 720×480 DIP，启动尺寸受当前工作区约束，不固定物理分辨率；宽度不足 1080 DIP 时检查区改为可展开侧层。主画面占剩余空间；两根分隔条分别调整来源列与检查区，实时限制宽度，不在松手后回跳；左右方向键可细调。图片始终等比留边，卡片不反向撑大分区。检查区按当前来源、运行状态、检测规则、采集范围、运行详情、来源管理分组排列；实际帧率与目标帧率分开显示，启停与状态同组，常用规则前置，遮罩和画面比例提示归入采集范围，远程镜头隐藏本地窗口和选区操作；运行中只读及不可用操作提供原因。更换采集目标取消或保存失败保留旧配置，不提供清空后保留空槽位的重置入口。菜单按钮、输入和下拉统一 36 DIP；标签列、操作列和间距保持一致。采样、冷却、置信度保留既有有界选项。
- 卡片内容按内圆角裁切，选中描边独立绘制于画面和标题之上。来源列表、检查区（含窄窗口侧层）与全局内容页复用分区滚动容器：内容视口与轨道间隔 12 DIP，轨道宽 10 DIP、距外沿 8 DIP；固定滚动槽避免滚动条出现时内容换行和卡片变宽。
- 全局设置在当前窗口内独立覆盖为分类子界面，提供账号与连接、推理与模型、外观、后台运行、版本与维护；返回恢复当前来源与滚动位置，页面切换不停止推理。模型资源按档位显示下载清单；来源选择只列本机已下载模型。失败原因可读，长度不符删除临时文件重下。
- 全局设置提供账号登录、退出和登录后的本机命名。发行版内置正式服务地址；Debug 或显式 `--isolated-environment` 才允许设置隔离服务地址。默认名称遵循[命名规范](15-命名规范.md)。共享 `AccountSession` 使用当前 Windows 用户的 DPAPI 加密会话，不保存密码；驻留与启动器沿用该会话。退出、撤销或换账号停止连接与推理并清理当前画面。
- 唯一设置入口 `Utils/SettingsStore.cs`，按服务、账号和设备写入 `%APPDATA%\VisionGuard\accounts/<scope>/settings.ini`，可用 `VISIONGUARD_SETTINGS_PATH` 指定独立父目录。设置存储通过显式静态构造在隔离参数生效后初始化；共享设置写入重读磁盘、合并改动、原子替换。`VISIONGUARD_ACCOUNT_DIR` 隔离会话、驻留配置与单实例标识；隔离实例不改 Windows 登录自启。
- 默认日志位于 `%LOCALAPPDATA%\VisionGuard`；隔离实例使用独立日志目录，`detector-crash.log`、`inference-error.log`、`resident-launch.log` 用于诊断。

## 后台驻留

后台驻留属于 视觉节点，随统一 Windows 包安装与更新；它有独立进程和工程标识，不作为单独应用。

- 检测端启动时拉起同目录驻留并等待单实例握手；驻留脱离父进程，自行登记登录启动。检测端退出后驻留继续存活；启动失败不阻断检测，但原因可见。
- WS 角色 `lifecycle`，节点类型 `resident`，平台 `windows`；与检测端共用 `deviceId` 和设备名称。名称以服务登记为准，`device-updated` 同步主节点、驻留和本地缓存，旧心跳不会覆盖控制台改名。
- 登录时由服务自动签发驻留子会话，驻留配置只引用共享账号目录，不含手填密钥。解绑、退出或改密后旧会话失效。
- 生命周期命令为 `open-detector` / `close-detector`；远程打开不自动开始检测。回执携带 `requestId`、`phase=completed` 与目标设备。
- 两者共用应用标识 `Detector` 与当前用户会话运行/退出事件；驻留配置每次启动由 JSON 序列化生成并回读自检。
- “完整退出”请求驻留退出并取消登录启动，确认退出后关闭主体；失败保留主体并说明原因。
- 检测端、驻留与启动器共同构成统一 Windows 包，不能只拷贝主程序。
