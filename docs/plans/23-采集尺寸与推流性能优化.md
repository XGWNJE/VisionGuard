# 采集尺寸与推流性能优化

负责：[待办 23](../06-待办.md) 的 Windows 采集尺寸与双推理端推流压缩需求。不负责：实现事实与验证证据。更新时机：需求调整时，完成或取消后随条目删除。未启动。

## Windows 采集尺寸

- 以用户设置的采集分辨率为依据，检查图像最长边是否超过 `640 × 1.5 = 960` 像素。
- 最长边不超过 960 像素时，不额外执行采集端压缩；超过时先压缩，再进入后续处理。压缩目标尺寸与具体方式结合现有链路评估确定。
- 本地推理模式先检查实际引擎流程：已具备等效尺寸处理、能够抵消该开销时，可跳过重复处理。
- 推流模式不能跳过尺寸压缩，应在进入后续链路前合理压缩图像，降低传输带宽。

## 固定镜头推流压缩

- 主要场景为固定镜头，画面长时间变化较少、短时间有明显动态；评估并优化视频流压缩算法，减少静态时不必要的数据传输。
- 动态出现时仍须满足实际推理需求；算法及参数根据画面质量、推理效果、带宽占用与实际性能测试共同确定，不预先指定算法。

完成条件：采集尺寸符合阈值和模式规则；双端推流方案通过静态与短时动态场景的质量、推理效果、流量及性能对比确定，证据归入[验证记录](../90-验证记录.md)。
