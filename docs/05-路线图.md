# 路线图

负责：后续方向、工程量排序与启动条件。不负责：本次任务进度、当前模块实现或验证证据。更新时机：owner 确认新的方向、范围或顺序时。

Web 是唯一控制台；Android 相机与通知节点继续支持手机和平板。Android 控制台已淘汰，源码、维护和服务接入已移除，历史发行资料保留。

## 后续开发

以下规划按预计工程量从小到大排序，仅登记方向、未排期；当前开发、修复与维护事项见[任务清单](06-任务清单.md)，证据与未覆盖项见[验证记录](90-验证记录.md)。真实使用问题由 owner 主动反馈后登记处理，不单列真实验收方向。工程量按当前实现粗估，需结合启动条件与依赖安排实际顺序；设备兼容性与局域网方案明确后再调整。

| 工程量顺序 | 规划内容 | 预计工程量与原因 | 范围、启动条件与依赖 |
|---|---|---|---|
| 1 | 将“视觉节点”改名为“视觉推理节点” | 小：主要为显示文案、默认名称、应用元数据及相关文档同步 | Windows 应用与后续 Android 推理应用统一使用新显示名；工程目录、包名、协议中的 `visual` 等技术标识不随显示名机械替换。实施前仍以[当前命名规范](15-命名规范.md)为准 |
| 2 | Web 控制台刷新保持登录，默认超过 24 小时重新登录 | 中：涉及浏览器会话保存 / 恢复、服务端有效期校验与自动续期边界 | 有效期内刷新恢复会话，不切回登录界面；默认从本次登录成功起计 24 小时，到期重新登录，刷新或自动续期不能无限延长。退出、撤销与账号失效及时清除会话；这是登录会话保持，与现有账号密码记忆分开处理 |
| 3 | 视觉推理节点接入 USB 有线摄像头或夜视摄像头，Android 支持 OTG 输入；按需扩展采集卡等视频输入 | 较大：增加采集来源，涉及 Windows / Android 两端的设备接入、格式和断连处理 | Windows 直接将 USB 摄像头作为推理输入；Android 视觉推理节点通过 OTG 接入外部摄像头，复用来源配置、遮罩、推理与报警链。按真实设备核对驱动、格式、供电及拔插恢复；Windows 部分可先做，Android 部分依赖原生推理节点；采集卡及其他视频设备按真实需要逐类接入现有节点职责 |
| 4 | 使用现成传感器、开发板和电池制作硬件原型 | 较大：涉及器件组合、现场检测、供电与续航验证 | 联网和告警现场验证之后确定组合；验证 2–8 米慢走和快速骑行场景、供电与续航，不提前设计 PCB |
| 5 | 使用原生 Android 复刻当前 Windows 视觉推理节点 | 大：新增完整推理端，覆盖原生界面、模型运行、多来源管理及告警链 | 对齐当前 Windows 的界面结构、来源管理、模型 / 检测参数、遮罩、报警、状态上报与控制台远控，适配手机和平板；Windows 专属窗口采集、选区及驻留机制按 Android 能力另行评估。具体工程、安装身份及与现有相机推流节点的关系在实施前确定；推理性能、发热与持续运行须真机验证 |
| 6 | 传感器融合、结构与电路板优化 | 很大，待细化：涉及多传感器协作及结构、电路设计与迭代 | 有硬件原型、设备性能与使用频率证据后再细化；Android 手机 / 平板推理由原生 Android 项统一覆盖 |
| 7 | 所有组件支持局域网与公网两种模式 | 预计最大，方案待定：涉及全组件连接、服务承载、认证、媒体、控制与通知链路 | 覆盖视觉推理、相机推流、通知节点、Web 控制台及统一服务。可能需要一个终端充当局域网服务端；由哪类终端承载、如何接入与切换，到启动此项时再规划，不提前确定实现。公网继续遵循统一服务转发边界 |

方向未排期，不表示已实现。原 Vigil 仍独立维护；架构职责见[当前架构](10-当前架构.md)。
