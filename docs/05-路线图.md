# 路线图

负责：后续方向、顺序、预计工程量与启动条件。不负责：本次任务进度、当前模块实现或验证证据。更新时机：owner 确认新的方向、范围或顺序时。

Web 是唯一控制台；Android 相机与通知节点继续支持手机和平板。Android 控制台已淘汰，源码、维护和服务接入已移除，历史发行资料保留。

## 后续开发

以下仅保留待开发方向，按 owner 确认的顺序编号，从通知节点锁屏问题继续推进。当前开发、修复与维护事项见[任务清单](06-任务清单.md)，证据与未覆盖项见[验证记录](90-验证记录.md)。真实使用问题由 owner 主动反馈后登记处理，不单列真实验收方向。工程量按当前实现粗估，需结合启动条件与依赖安排实际顺序；设备兼容性与局域网方案明确后再调整。

| 顺序 | 规划内容 | 预计工程量与原因 | 范围、启动条件与依赖 |
|---|---|---|---|
| 1 | 深度验证并修复通知节点锁屏后告警接收问题 | 较大，修复量待根因确认：涉及长时间真机验证、后台运行、连接恢复与完整报警链 | 以小米 15 为目标，先确认真实锁屏且不受蓝牙自动解锁影响；通过真实服务器独立测试通道与实际组件，覆盖短时 / 较长锁屏、期间多次报警、断连重连及解锁后的表现。分别取证后台服务存活、服务转发、节点收件持久化与声音播放，记录漏收时间、日志及是否补收，定位后修复并回归。解锁按[已授权的环境变量入口](60-构建验证与发布.md#设备验收操作)读取，不记录密码；设备测试全程静音，以收件回执、持久化与队列等证据验证送达；静音结果不证明可听声音 |
| 2 | 使用现成传感器、开发板和电池制作硬件原型 | 较大：涉及器件组合、经过 / 防拿走 / 声响检测、供电与续航验证 | 室外固定，监测人或骑行者经过、设备被移动 / 拆走，以及突发大声 / 撞击等明显声响变化；首轮预算 500 元以内，先用 Wi-Fi / 手机热点。设计、采购与选型条件见[硬件原型专题](25-硬件原型设计与采购.md)；现场验证后确定组合，不提前设计 PCB |
| 3 | 使用原生 Android 复刻当前 Windows 视觉推理节点 | 大：新增完整推理端，覆盖原生界面、模型运行、多来源管理及告警链 | 对齐当前 Windows 的界面结构、来源管理、模型 / 检测参数、遮罩、报警、状态上报与控制台远控，适配手机和平板；Windows 专属窗口采集、选区及驻留机制按 Android 能力另行评估。具体工程、安装身份及与现有相机推流节点的关系在实施前确定；推理性能、发热与持续运行须真机验证 |
| 4 | 传感器融合、结构与电路板优化 | 很大，待细化：涉及多传感器协作及结构、电路设计与迭代 | 有硬件原型、设备性能与使用频率证据后再细化；Android 手机 / 平板推理由原生 Android 项统一覆盖 |
| 5 | 所有组件支持局域网与公网两种模式 | 预计最大，方案待定：涉及全组件连接、服务承载、认证、媒体、控制与通知链路 | 覆盖视觉推理、相机推流、通知节点、Web 控制台及统一服务。可能需要一个终端充当局域网服务端；由哪类终端承载、如何接入与切换，到启动此项时再规划，不提前确定实现。公网继续遵循统一服务转发边界 |

实施进度以任务清单为准。原 Vigil 仍独立维护；架构职责见[当前架构](10-当前架构.md)。
