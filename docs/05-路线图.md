# 路线图

负责：后续方向、顺序、预计工程量与启动条件。不负责：本次任务进度、当前模块实现或验证证据。更新时机：owner 确认新的方向、范围或顺序时。

Web 是唯一控制台；Android 相机与通知节点继续支持手机和平板。Android 控制台已淘汰，源码、维护和服务接入已移除，历史发行资料保留。短期部署以 Android 相机推流节点为主要采集单元，同源 `/camera/` 页面提供 Web 相机推流节点作为第二实现；两者都接入现有 Windows 视觉推理节点、统一服务、控制台与通知节点。

## 后续开发

以下仅保留待开发方向，按 owner 确认的顺序编号。当前开发、修复与维护事项见[任务清单](06-任务清单.md)，证据与未覆盖项见[验证记录](90-验证记录.md)。顺序 1 已降级为待外部条件（owner 线索指向设备端系统策略），其余方向等 owner 确认启动顺序。真实使用问题由 owner 主动反馈后登记处理，不单列真实验收方向。工程量按当前实现粗估，需结合启动条件与依赖安排实际顺序；设备兼容性与局域网部署方案明确后再调整。顺序 5、6 属硬件方向，短期不再推进，设计与采购条件保留；顺序 4 的低成本多点位依赖硬件原型，也不会先启动。

| 顺序 | 规划内容 | 预计工程量与原因 | 范围、启动条件与依赖 |
|---|---|---|---|
| 1 | 深度验证并修复通知节点锁屏后告警接收问题（**已降级：待外部条件**） | 较大，修复量待根因确认：涉及长时间真机验证、后台运行、连接恢复与完整报警链 | 以小米 15 为目标，先确认真实锁屏且不受蓝牙自动解锁影响；通过真实服务器独立测试通道与实际组件，覆盖短时 / 较长锁屏、期间多次报警、断连重连及解锁后的表现。分别取证后台服务存活、服务转发、节点收件持久化与声音播放，记录漏收时间、日志及是否补收，定位后修复并回归。解锁按[已授权的环境变量入口](60-构建验证与发布.md#设备验收操作)读取，不记录密码；设备测试全程静音，以收件回执、持久化与队列等证据验证送达；静音结果不证明可听声音。**当前判断（2026-10-12）**：同一账号在小米 6X 上不存在给了权限仍被杀后台，而该机在售后换电池时可能被改动过后台策略——更像设备端问题，等换机或系统重置后再看，见[任务清单](06-任务清单.md#未完成事项) |
| 3 | 局域网与公网两种**部署模式** | 预计最大，方案待定：涉及两种部署下的组件连接、服务承载、认证、媒体、控制与通知链路 | 目标：局域网部署换来**更低延迟、更大带宽吞吐**，并让画面与报警数据不必离开本地网络（隐私）。两套彼此独立的部署，**不是同一部署内的运行时可切换模式**：公网部署沿用统一服务转发；局域网部署由本地网络里的一台终端承载服务，各组件指向它。不设计双入口探测、自动降级或在线切换——换部署等于换一套安装与配置。覆盖视觉推理、相机推流、通知节点、Web 控制台与统一服务；局域网由哪类终端承载、如何接入，到启动此项时再规划 |
| 4 | 低成本多点位传感器方向（蓝牙成品加 ESP32 网关） | 待细化：涉及 BLE 广播解析、传感器通道契约、扫描功耗与室外误漏报 | 用便宜的蓝牙 PIR 成品铺高密度点位，一个 ESP32 网关扫描广播并按现有传感器事件上报；不计入首轮 500 元预算，待单雷达原型链路跑通且确认需要高密度低价点位后启动，不先铺点位。原理、代价与契约缺口见[硬件原型专题](25-硬件原型设计与采购.md#备选方向低成本多点位传感器) |
| 5 | 使用现成传感器、开发板和电池制作硬件原型 | 较大：涉及器件组合、经过 / 防拿走 / 声响检测、供电与续航验证 | 室外固定，按已选 25m 版雷达的标称上限把经过检测目标定在 25 米级开阔面，监测人或骑行者经过、设备被移动 / 拆走，以及突发大声 / 撞击等明显声响变化；实际检出距离与误漏报实测确定，不承诺 25 米。首轮预算 500 元以内，先用 Wi-Fi / 手机热点。设计、采购与选型条件见[硬件原型专题](25-硬件原型设计与采购.md)；现场验证后确定组合，不提前设计 PCB |
| 6 | 传感器融合、结构与电路板优化 | 很大，待细化：涉及多传感器协作及结构、电路设计与迭代 | 有硬件原型、设备性能与使用频率证据后再细化；Android 手机 / 平板推理由原生 Android 项统一覆盖 |

实施进度以任务清单为准；已完成的方向不再占表：顺序 2（原生 Android 推理节点）随 0.6.12 完成，应用内更新入口随 0.7.0 上线，实现事实见 [Android 推理专题](31-Android视觉推理节点.md)。原 Vigil 仍独立维护；架构职责见[当前架构](10-当前架构.md)。
