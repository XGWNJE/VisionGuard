# Android 视觉推理节点

负责：Android 视觉推理节点的实现事实与平台限制。不负责：任务状态或验证报告。更新时机：实现或约束变化时。任务归属见[待办](06-待办.md)，证据及未覆盖项见[验证记录](90-验证记录.md)。

## 工程与身份

`detector/android-inference/` 是独立 Compose 应用，显示名“视觉推理节点”，包名 `com.xgwnje.visionguard.inference`。与相机推流、通知应用分别安装、保存账号及设备身份，共用 `android-shared/` 的账号、主题和官方 Lucide 资源。两份推理实现的正式包名相同，比较安装使用各自隔离预览包。

登录组件 `android-inference`，协议身份 `detector / visual / android`，不签发 Windows 驻留子会话。只执行推理、不发布视频；本机相机由 CameraX 采集，远程镜头经统一服务 `/media/ws` 订阅，不另建服务或控制台。

## 来源与检测

检测链：`Capture → MaskApply → Letterbox → LiteRT GPU / ONNX CPU → Parse → AlertDecision → Outbox`。

- 本机来源固定为 `camera`；绑定的远程镜头通过 `stream-list` 自动加入、移除，来源标识稳定。服务下发来源上限 1–16；同时运行的来源数另受**本机推理能力**限制（按「模型 + 后端」定，见[多路限制](32-推理框架与模型优化.md#多路限制单路-5-帧秒)），已绑定来源完整展示，启动时按实际后端限制运行路数。每路独立运行与报错，忙时保留最新帧。
- 作为被动方可以解除远程来源的绑定：来源详情的采集与来源页在远程来源下多一段「远程绑定」，说明这条绑定按发布端生效（解除后该发布端的所有来源一起停推本机），二次确认后调 `POST /api/streams/unbind`；成功后不手工删本地来源，等 `stream-list` 变化自动移除。没记下发布端身份的旧来源不给本机操作，只提示到控制台处理。
- 来源名最多 64 个 UTF-16 单元且无控制字符；置信度 10–95% 整数、采样 1–5 FPS、冷却 1–300 秒、COCO 英文目标最长 4096 字符。模型与参数停止后保存，下次启动生效，本机及远控共用校验。
- 遮罩用 `[0,1]` 相对坐标，推理前涂黑；预览和截图复用已遮罩画面，遮罩不通过远控同步。
- 用户只选择 M320 / M640（键为 `yolo26m_320` / `yolo26m_640`）。每档下载同尺寸 INT8 ONNX 与 GPU TFLite，两个文件均校验成功才可选；无完整模型时不默认选择。兼容时自动优先 GPU，失败回落同尺寸 INT8 并报告实际后端；不提供后端优先级设置。
- 解析验证输出展平长度，识别 `[1,300,6]`（模型内 NMS）或 `[1,84,N]`（**锚点档，图内无 NMS**）。锚点档前 4 通道按「0/2 为一对 x、1/3 为一对 y」配对解码——顺序与端到端档 `x1,y1,x2,y2` 不同，照搬会静默出错框；逐类 NMS 后映射回原帧。两档都最多返回 5 框。
- 远程帧格式为 4 字节大端头长、JSON、JPEG：头 ≤4096 字节、JPEG ≤2 MiB、最长 / 短边 ≤1280 / 720、旋转仅 0/90/180/270，声明尺寸须与实际一致。

## 报警、状态与远控

NTP 校正报警时间，逐来源独立冷却。账号 / 服务 / 设备分区的持久 outbox 最多 500 项，超出丢最旧；实时期限 30 秒，过期不补发。收到接受回执后移除事件并异步发送截图（宽 ≤960，JPEG 65）；确定拒收 `alert-id-conflict`、`invalid-or-expired-event` 同样移除，其他拒收保留重试。

心跳每 3 秒上报运行意图 `monitoringExpected`、成功处理时间 `lastProgressAt`、FPS、后端与后端细节（`backendNote`，含输入尺寸、加速器可见性与「为何没用 GPU」）、参数、错误，以及本机推理能力（`inferenceLimits` / `inferenceBackends` / `overConcurrencyLimit`）与逐来源 `concurrencyLimit`。成功帧才推进进度；FPS 低于目标 80% 连续 30 秒提示性能不足。

控制台复用现有操作入口，命令逐条返回 completed 回执：

- `pause` / `resume` 可指定来源；设备级作用于全部来源。`remove-source` 只允许删除已停止的指定来源，远程来源按发布端解除绑定，等待服务目录移除卡片。
- `set-config` 支持置信度、冷却、目标、采样和模型五个键；运行中拒绝，未指定来源时作用于第一个来源。
- `cache-inspect` / `cache-clean` 回传清理结果；`stop-alarm` 回报“当前无报警”。不接收 Windows 的 `open-detector` / `close-detector`，不声明 `directml`。

## 后台运行

有来源运行时使用 `InferenceService`；后台、锁屏与进程回收服从系统限制，不保证后台推理。系统相机权限仍需本机授权，不修改锁屏、唤醒或后台限制。Android 调试串行执行，持续推理只在应用前台验证；运行意图持久化、主动停止清除意图。

## 界面

主工作区包含预览、来源列表与底部状态带，宽屏并排、窄屏堆叠。点来源切换预览，行尾打开来源抽屉，逐来源启停。抽屉分概览、采集与来源、检测规则、遮罩；规则与遮罩独立草稿，离开前可保存、放弃或继续编辑，运行中只读。概览显示实际后端、帧率、耗时、画面与报警时间及当前实例帧数，停止时明确为最后记录。

设置使用「节点状态、账号与设备、模型资源、外观、后台与权限、维护」分类，窄屏目录进入详情，宽屏侧栏导航。节点状态独立呈现控制、媒体、收帧、服务时钟、当前进程累计报警与待服务回执；这些状态不代表通知收件或声音播放。预览构建的维护区保留模拟场景开关，正式构建不显示；本地预览统一走 `scripts/ui-preview.ps1`，只读复用服务资源，来源绑定和权限仍服从实际能力。界面保留品牌颜色，布局与控件按场景适配，不受旧几何布局约束。

账号会话用 Keystore 保存并排除系统备份；来源参数、报警元数据和截图按账号分区。模型下载取**当前登录会话所在的服务地址**（本地服务版即局域网服务），不是构建时写死的正式地址；没有会话时才回落到内置地址。截图缓存限 7 天 / 200 项 / 100 MB，清理不触及模型、账号或配置。

## 推理加速

M320 / M640 自动选择可用后端：兼容时用 LiteRT GPU 截断图，否则用同尺寸 ONNX INT8（intra / inter 线程 4 / 1），原因写入 `backendNote`。NNAPI 与 NPU 不参与正式链路；测量和并发依据见[推理框架](32-推理框架与模型优化.md#正式档位与限制)。

每个来源在固定工作线程上创建、运行、释放引擎；LiteRT 复用输入 / 输出 TensorBuffer 与 NHWC 临时数组，退出时释放缓冲、模型与环境。模型初始化先于相机采集，相机转换按来源目标 FPS 限速；停止和释放不在主线程等待 GPU。

## 构建与未实现项

构建入口为 `.agents/skills/visionguard-build/scripts/build-all.ps1 -Target AndroidInference`，版本读取根 `VERSION`；当前所有 ABI 合入一个 APK。签名所需材料仅放忽略文件或环境变量，构建结果见验证记录。

**已接入发布流水线**：`publish-release.ps1` 的平台表含 `android-inference`，产出 `VisionGuard-Inference-v<版本>.apk` 并写入更新元数据（`/api/update?platform=android-inference`）。应用内「检查更新 → 下载安装」入口在「设置 → 维护」：`android-shared` 的 `ClientUpdater` 查 GitHub 稳定发行（与相机、通知节点同一机制），做版本比较、下载、sha256 与包名/版本/签名校验，再交给系统安装器；**它依赖发布时把推理节点包上传到 GitHub 发行**。
