# Android 视觉推理节点

负责：Android 视觉推理节点的实现事实与平台限制。不负责：任务状态或验证报告。更新时机：实现或约束变化时。任务归属见[任务清单](06-任务清单.md)，界面视觉底线见[几何空间视觉语言参考](73-几何空间界面规范.md)，证据及未覆盖项见[验证记录](90-验证记录.md)。

## 工程与身份

`detector/android-inference/` 是独立 Compose 应用，显示名“视觉推理节点”，包名 `com.xgwnje.visionguard.inference`。与相机推流、通知应用分别安装、保存账号及设备身份，共用 `android-shared/` 的账号、主题和官方 Lucide 资源。两份推理实现的正式包名相同，比较安装使用各自隔离预览包。

登录组件 `android-inference`，协议身份 `detector / visual / android`，不签发 Windows 驻留子会话。只执行推理、不发布视频；本机相机由 CameraX 采集，远程镜头经统一服务 `/media/ws` 订阅，不另建服务或控制台。

## 来源与检测

检测链：`Capture → MaskApply → Letterbox → ONNX Runtime → Parse → AlertDecision → Outbox`。

- 本机来源固定为 `camera`；绑定的远程镜头通过 `stream-list` 自动加入、移除，来源标识稳定。服务下发来源上限 1–16；同时运行的来源数另受**本机推理能力**限制（按「模型 + 后端」定，见[多路限制](32-推理框架与模型优化.md#多路限制单路-5-帧秒)；INT8 两档的上限待真机补测，当前按保守值拦截），超限时新增被拒并给出可读原因。每路独立运行与报错，忙时保留最新帧。
- 来源名最多 64 个 UTF-16 单元且无控制字符；置信度 10–95% 整数、采样 1–5 FPS、冷却 1–300 秒、COCO 英文目标最长 4096 字符。模型与参数停止后保存，下次启动生效，本机及远控共用校验。
- 遮罩用 `[0,1]` 相对坐标，推理前涂黑；预览和截图复用已遮罩画面，遮罩不通过远控同步。
- 模型只保留 4 档：GPU 档 `yolo26m_320` / `yolo26m_640` **只下载 `<键>_gpu.tflite` 截断图**（不含 ONNX 本体），CPU 档 `yolo26m_320_int8` / `yolo26m_640_int8` 下载 `<键>.onnx`；都在来源参数抽屉的「模型插槽」里按需下载到私有 `files/models/`，长度校验后替换，未下载的档位不可选中，清单外的旧文件由本机清理。等比缩放补黑边，输入 CHW RGB `/255`。GPU 档走 LiteRT GPU（见下文「推理加速」），CPU 档走 ONNX Runtime CPU（intra / inter 线程为 4 / 1）。
- 解析验证输出展平长度，识别 `[1,300,6]`（模型内 NMS）或 `[1,84,N]`（**锚点档，图内无 NMS**）。锚点档前 4 通道按「0/2 为一对 x、1/3 为一对 y」配对解码——顺序与端到端档 `x1,y1,x2,y2` 不同，照搬会静默出错框；逐类 NMS 后映射回原帧。两档都最多返回 5 框。
- 远程帧格式为 4 字节大端头长、JSON、JPEG：头 ≤4096 字节、JPEG ≤2 MiB、最长 / 短边 ≤1280 / 720、旋转仅 0/90/180/270，声明尺寸须与实际一致。

## 报警、状态与远控

NTP 校正报警时间，逐来源独立冷却。账号 / 服务 / 设备分区的持久 outbox 最多 500 项，超出丢最旧；实时期限 30 秒，过期不补发。收到接受回执后移除事件并异步发送截图（宽 ≤960，JPEG 65）；确定拒收 `alert-id-conflict`、`invalid-or-expired-event` 同样移除，其他拒收保留重试。

心跳每 3 秒上报运行意图 `monitoringExpected`、成功处理时间 `lastProgressAt`、FPS、后端与后端细节（`backendNote`，含输入尺寸、加速器可见性与「为何没用 GPU」）、参数、错误，以及本机推理能力（`inferenceLimits` / `inferenceBackends` / `overConcurrencyLimit`）与逐来源 `concurrencyLimit`。成功帧才推进进度；FPS 低于目标 80% 连续 30 秒提示性能不足。

控制台复用现有操作入口，命令逐条返回 completed 回执：

- `pause` / `resume` 可指定来源；设备级作用于全部来源，来源不存在时拒绝。
- `set-config` 支持置信度、冷却、目标、采样和模型五个键；运行中拒绝，未指定来源时作用于第一个来源。
- `cache-inspect` / `cache-clean` 回传清理结果；`stop-alarm` 回报“当前无报警”。不接收 Windows 的 `open-detector` / `close-detector`，不声明 `directml`。

## 后台运行

有来源运行时启用 `InferenceService` 前台服务，退后台或锁屏继续推理；运行意图持久化，进程被系统回收后按意图恢复，主动停止清除意图。系统相机权限仍需本机授权，不修改锁屏或唤醒设置；真机后台存活以验证记录为准。

## 界面

视觉上按[几何空间视觉语言参考](73-几何空间界面规范.md)保持直角几何、1dp 描边与青色主色（布局不再按规范数字落地）：全屏运行、无顶部标题行，应用级入口在底部状态带右端。横屏为「上两栏 + 底部一条」：上栏左侧主预览、右侧来源列表（宽 300dp），底部状态带左段与预览同宽（仪表读数 + 参数摘要）、右段与来源列表同宽（连接状态 + 帮助 / 设置 / 账号），两处分界对齐；运行状态只在预览标题行说一次，标题行右侧给出画面尺寸。窄屏上下堆叠、状态带整条不分段。几何空间界面已全部落地：几何组件层（压板操作键、图标键、拨档、滚筒、滑轨、右侧抽屉、信息带、危险确认）、主工作区、遮罩抽屉（26dp 内衬、四角把手、坐标列表与清空闸门）、全局设置抽屉（账号、模型、外观、后台、维护五个分区；宽屏为左栏分区导航＋右栏内容两栏）与可折叠帮助；旧 Material 界面与工具已删除。来源、检测参数与遮罩合并成一个「来源抽屉」，用拨档切三页：来源页承载身份、两列状态网格、名称、镜头与删除，检测参数页把采样、置信度、冷却排成逐段等高的三列、下面是模型插片与检测目标两列（模型插片是下载、删除与选择的唯一入口），遮罩页承载工具键、画布与遮罩列表；每页页脚独立（来源页关闭，参数页还原 / 取消 / 保存参数，遮罩页还原 / 取消 / 保存遮罩），参数与遮罩草稿互不影响。入口只在来源行：点行切换预览、行尾方键打开抽屉、行内 ▶ / ⏸ 逐来源启停；主界面不再有整体启停与参数、遮罩方键，来源列表表头在有来源运行时提供「全部停止」。需要解释的参数在区块标题右侧给出「?」，跳到帮助页并展开对应条目（帮助共 8 条）。本机相机默认登记：进入界面时若列表里还没有就自动创建一条，界面不提供「添加来源」入口；远程来源仍由相机推流绑定或控制台设定后下发，本机不自行创建槽位。无来源时直接进入主工作区（预览区显示占位、来源滑架只剩添加来源），不另设独立空来源界面，此时参数与遮罩为禁用态。预览构建在「设置 → 维护 → UI 验收」可切一份覆盖多来源、异常态与长文本的模拟数据，用于界面验收；正式构建不显示该入口。UI 预览包（`.uipreview`）构建时内置本地服务通道、局域网地址与预览账号：启动先在局域网发现服务并静默登录，服务换端口不用重装；要调登录流程时在登录页的「本地服务设置」里勾选停在登录界面；正式包不含凭据，行为不变。本地服务版「设置 → 维护」的更新检查指向本地服务（`/api/local/releases`），可离线演练组件下载。全局设置含账号、推理状态、外观、后台、版本与维护（模型清单只在参数抽屉里管理），帮助页解释操作边界；沿用[统一 UI 规范](70-UI设计规范.md)。

账号会话用 Keystore 保存并排除系统备份；来源参数、报警元数据和截图按账号分区。模型下载取**当前登录会话所在的服务地址**（本地服务版即局域网服务），不是构建时写死的正式地址；没有会话时才回落到内置地址。截图缓存限 7 天 / 200 项 / 100 MB，清理不触及模型、账号或配置。

## 推理加速

**两条路线，按模型选后端**（口径与全矩阵读数见[推理框架与模型优化](32-推理框架与模型优化.md#验收口径)）：

- **CPU 档 = ONNX Runtime · CPU 4 线程 + INT8**：只有两个量化档（`yolo26m_{320,640}_int8`），CPU 不跑 FP32。
- **GPU 档 = LiteRT GPU + 截断图**：后端随档位绑定，选中 GPU 档即走 GPU；设备不支持或加载失败时**回落到同尺寸 INT8** 并把原因写进来源状态（`backendNote`，如「本机不支持 LiteRT GPU 加速器」「GPU 模型加载失败」），不静默降级。端到端实测（同 API CPU 基线 290.2 ms）：640-m 单路 **67.0 ms**、帧率 15.9，解码 + NMS 仅 0.9–1.8 ms；320 档产物待生成与实测。
- 设置里每个档位直接标出跑在哪：`GPU` / `CPU`（判定与引擎选择同一口径）。
- **NNAPI 与 NPU 已放弃**：NNAPI 在这条链上是负优化（同机 MT8910 上 yolo26m · 640 四档 1737.8–2251.8 ms，CPU 335.0 ms——系统加速器把图切碎后跨设备拷贝的开销超过加速收益）；NPU 缺公开接口，不申请厂商 SDK 无路可走。
- 量化档固定走 ONNX CPU，不参与加速：它们只有 `.onnx`，边界是 float32、图内 int8，而 LiteRT 需要按 scale 换算整数边界。

## 构建与未实现项

构建入口为 `.agents/skills/visionguard-build/scripts/build-all.ps1 -Target AndroidInference`，版本读取根 `VERSION`；当前所有 ABI 合入一个 APK。签名所需材料仅放忽略文件或环境变量，构建结果见验证记录。

**已接入发布流水线**：`publish-release.ps1` 的平台表含 `android-inference`，产出 `VisionGuard-Inference-v<版本>.apk` 并写入更新元数据（`/api/update?platform=android-inference`）。应用内「检查更新 → 下载安装」入口在「设置 → 维护」：`android-shared` 的 `ClientUpdater` 查 GitHub 稳定发行（与相机、通知节点同一机制），做版本比较、下载、sha256 与包名/版本/签名校验，再交给系统安装器；**它依赖发布时把推理节点包上传到 GitHub 发行**。
