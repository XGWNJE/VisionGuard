# Android 检测端控制台 UI 设计规格

## 背景

Android 检测端不是普通手持应用，而是长期架设在现场的检测设备。新 UI 的目标是为实体部署、横竖安装、短时校准和长时监控建立稳定地基，同时复用 Android 接收端已确认的视觉语言。

本规格只覆盖 `detector/android/` 的 UI 与状态结构设计，并约束接收端远程调参的交互语义。实现计划另行编写。

## 目标

- 将检测端从“监控 / 设置”传统 App 结构改为“架设型设备控制台”。
- 横屏和竖屏使用两套完整布局，而不是轻量自适应。
- 运行态不长期持有实时预览，只展示最近帧和按需校准抓拍。
- 校准取景、遮罩编辑、模型/分辨率/裁切等影响推理链的配置走冷操作。
- 远程参数允许在监控中编辑保存，但不热应用；停止后重新启动监控时生效。
- 视觉上复用接收端 Android UI 规范的颜色、圆角、浮层、状态和按钮语义。

## 非目标

- 不引入长期 CameraX Preview 作为首页实时画面。
- 不新增模型管理独立页面；模型状态仍在模型选择处显示。
- 不恢复旧 HTML 原型、旧 Pencil 方案或一次性设计脚本。
- 不自动升级版本号，不改发布流程。
- 不在第一版实现热应用配置。

## 视觉语言

检测端使用接收端规范中的核心 token，可在检测端代码中按端名重命名，但语义保持一致：

- 背景：浅绿 `#F1F6F1`
- Surface：近白 `#FAFCF8`
- 次级 Surface：`#E9F0EA`
- 主色：深绿 `#1F4638`
- 辅助文本：灰绿 `#727C75`
- 未就绪 / 待生效：琥珀色
- 报警 / 停止 / 危险动作：红色

检测端要比接收端更像设备面板：画面区域更大、状态更集中、主操作按钮更明显、解释性文字更少。

## 信息架构

### 1. 哨位运行

默认第一屏，服务长期监控状态。

显示内容：

- 服务器连接状态
- 监控运行状态
- 模型就绪状态
- 实际采样率与目标采样率
- 当前生效模型、输入尺寸、目标类别、冷却时间
- 最近报警时间
- 最近帧区域
- 待生效参数提示
- 未校准建议提示

主要动作：

- 开始监控
- 停止监控
- 刷新最近帧
- 进入架设校准（仅停止时）
- 打开维护参数
- 重连服务器

### 2. 架设校准

短时维护工作台，只能在监控停止时进入。

显示内容：

- 按需抓拍的校准帧
- 遮罩矩形
- 数码裁切框
- 当前遮罩数量
- 当前裁切倍率

主要动作：

- 重新抓拍
- 画遮罩
- 撤销遮罩
- 清空遮罩
- 调整数码裁切
- 应用配置
- 取消

### 3. 维护参数

配置与维护入口，可在监控中打开并编辑，但监控中保存的变更只进入 `DraftConfig`，不影响当前运行。

内容分组：

- 部署方向：竖屏架设 / 横屏架设
- 设备名称
- 模型与输入尺寸
- 高分辨率开关与 SoC 能力提示
- 目标类别
- 置信度
- 目标采样率
- 报警冷却时间
- 服务器连接与重连
- 版本更新

## 横竖屏布局

### 竖屏运行台

```text
+--------------------------------+
| [已连接] 监控中     实际 3.0/s   |
+--------------------------------+
| 最近帧 12:48          [刷新]      |
|                                |
|        报警/校准快照画面           |
|        非实时预览                 |
|                                |
+--------------------------------+
| Android-Detector               |
| YOLO26n 320  人员  冷却30秒       |
| 模型已就绪  最近报警12:48          |
+--------------------------------+
|          [ 停止监控 ]             |
| [校准取景] [维护参数] [重连]        |
+--------------------------------+
```

竖屏不做传统大标题；顶部状态胶囊就是主状态模块。底部使用操作坞承载主动作，不把所有功能做成底部 Tab。

### 横屏运行台

```text
+--------------------------------------+----------------------+
| 最近帧 12:48                 [刷新]   | [已连接] 监控中       |
|                                      | 实际 3.0/s            |
|          报警/校准快照画面             |                      |
|          非实时预览                   | [停止监控]            |
|                                      | [停止后校准] disabled |
|                                      | [维护参数]            |
|                                      | 模型 YOLO26n 320     |
+--------------------------------------+----------------------+
```

横屏不放底部导航。左侧是画面和最近帧，右侧是固定控制塔，适合手机横向架设后快速扫一眼状态。

### 停止后校准台

```text
+--------------------------------------+----------------------+
| 校准帧                       [重抓拍] | 架设校准              |
|                                      | 遮罩 2 个             |
|          抓拍预览画布                 | 数码裁切 1.0x         |
|                                      | [撤销] [清空]         |
|                                      | [取消] [应用配置]     |
+--------------------------------------+----------------------+
```

竖屏校准使用上方画布、下方工具；横屏校准使用左侧画布、右侧工具。两者共享遮罩编辑模型，不共享布局容器。

## 方向策略

方向采用手动部署策略，不默认自动旋转。

首次启动：

- 显示轻量部署方向选择：`竖屏架设` / `横屏架设`。
- 用户选择后写入设置。
- 未选择前不进入主控制台。

后续修改：

- 在维护参数中提供部署方向设置。
- 修改后应用 Activity 请求方向，进入对应布局。
- 第一版不做自动方向缓冲，因为默认不是自动旋转。

## 预览与帧策略

运行态：

- 显示最近报警帧或最近一次校准抓拍帧。
- 没有最近帧时显示空状态：“暂无最近帧，停止后可校准取景”。
- “刷新最近帧”只请求一次抓拍或快照，不持续预览。
- UI 文案必须明确“最近帧”，不得暗示实时预览。

校准态：

- 进入时按需抓拍一帧。
- 点击“重新抓拍”再取一帧。
- 遮罩与数码裁切基于当前校准帧编辑。
- 退出校准后停止取帧。

## 配置状态模型

引入清晰的运行配置语义：

- `AppliedConfig`：当前监控进程实际使用的配置。
- `DraftConfig`：本地或远程编辑后的配置，持久化到 DataStore。
- `HasPendingChanges`：监控中 `DraftConfig != AppliedConfig` 时为 true。
- `CalibrationState`：校准会话状态，包含校准帧、遮罩草稿和裁切草稿。
- `DeploymentOrientation`：`portrait` 或 `landscape`。

第一版不实现 `PendingChange` 队列；只需要通过 `HasPendingChanges` 告知“已保存，重启监控后生效”。

## 冷操作规则

监控中禁止：

- 进入校准取景
- 进入遮罩编辑
- 应用模型切换
- 应用输入尺寸变化
- 应用高分辨率开关
- 应用数码裁切变化
- 应用遮罩变化

监控中允许：

- 打开维护参数
- 编辑参数并保存到 `DraftConfig`
- 显示“有参数待生效，停止后重新开启应用”
- 停止监控
- 重连服务器
- 检查更新

停止后允许：

- 进入校准取景
- 编辑遮罩
- 应用所有参数
- 启动监控时用 `DraftConfig` 作为新的 `AppliedConfig`

## 启动前检查

未校准时允许启动监控，但不推荐。

UI 行为：

- 未校准或无最近校准帧时显示琥珀提示：“建议先校准取景”。
- 开始监控按钮仍可用。
- 首次启动监控前，如果未校准，弹一次轻量确认：“尚未校准取景，仍要开始监控吗？”
- 用户确认后继续启动，避免强制阻断现场部署。

## 远程参数语义

接收端远程调参需要与检测端本地语义一致。

检测端监控中收到远程 `set-config`：

- 写入 DataStore / `DraftConfig`。
- 不调用会影响当前监控链路的热应用逻辑。
- 返回 ack 文案语义：“已保存，重启监控后生效”。
- 下一次心跳应能表达存在待生效参数，供接收端显示。

检测端停止时收到远程 `set-config`：

- 写入 DataStore / `DraftConfig`。
- 更新本地 UI 草稿。
- 下次启动监控直接生效。

接收端设备参数面板：

- 监控中仍允许编辑。
- 应用按钮文案保持“保存参数”或“保存更改”，不说“已应用”。
- 保存后显示“已保存，停止后重新开启生效”。

## 组件拆分

建议拆分为以下边界：

- `MainActivity`：权限、Service 启动绑定、Activity 方向请求、`setContent`。
- `DetectorConsoleRoute`：收集 Service flows 与 DataStore，构造 UI state，分发 action。
- `DetectorConsoleState`：纯 UI 状态模型，可 JVM 测试。
- `DetectorConsoleModels`：文案、状态 tone、布局参数、按钮可用性。
- `DetectorConsoleScreen`：选择竖屏或横屏布局。
- `PortraitConsole`：竖屏运行台。
- `LandscapeConsole`：横屏运行台。
- `CalibrationWorkspace`：校准工作台入口。
- `PortraitCalibration`：竖屏校准布局。
- `LandscapeCalibration`：横屏校准布局。
- `MaintenanceSheet`：维护参数底部表单或横屏侧栏。
- `DetectorTheme`：检测端主题 token，语义对齐接收端规范。

`MainActivity` 不再直接持有大量配置保存与 UI 展示逻辑。

## 错误与边界状态

- Service 未绑定：显示加载状态，不进入控制台。
- 摄像头权限缺失：显示权限引导和重试入口，不启动服务监控。
- 模型未下载：在模型选择处显示下载状态，启动监控时触发下载；失败显示通知和 UI 错误。
- 服务器断开：状态胶囊显示断开，重连按钮可用。
- 认证失败：状态胶囊红色，提示检查 API Key。
- 校准抓拍失败：留在校准台，显示失败原因和“重新抓拍”。
- 方向未选择：停留在部署方向选择，不显示主控制台。

## 验证要求

设计实现后至少验证：

- `detector/android` 新增 UI model JVM 测试。
- `detector/android` `:app:testDebugUnitTest`。
- `detector/android` `:app:assembleDebug`。
- 真机或模拟器竖屏截图：运行台、维护参数、校准台。
- 真机或模拟器横屏截图：运行台、维护参数、校准台。
- 监控中校准入口不可进入。
- 监控中远程保存参数后当前运行不热变更，停止再启动后生效。
- 未校准启动监控有推荐校准提示，但允许继续。
- 方向设置为竖屏/横屏后 Activity 不随安装过程中的物理旋转频繁切换。
