# VisionGuard UI 设计规范

负责：当前界面标准、组件组织与适配范围。不负责：业务契约、任务和验证证据。更新时机：设计或实现边界变化时；实际检查只记在[验证记录](90-验证记录.md)。

## 控制台设计基准

Web 控制台采用官方 [shadcn/ui](https://ui.shadcn.com/docs) Neutral／Radix Nova，直接组合 CLI 获取的真实组件；配置在 receiver/web/components.json，组件在 src/components/ui/。使用语义 CSS 变量与官方 [Vite ThemeProvider](https://ui.shadcn.com/docs/dark-mode/vite)，以根 .dark 类切换跟随系统／浅色／深色并保存本机偏好。正文与次级文字使用官方 foreground／muted-foreground，不另设页面调色板。

- 本地打包 Geist，中文回退系统无衬线；正文 14／20、辅助 12／18、页面标题 24／32、CardTitle 16／24，单位 rem。字体与组件许可证随 public/third-party/ 分发。
- 间距 4／8／12／16／24／32；根圆角 .625rem，控件和卡片采用官方尺寸、圆角与变体。按钮、输入、下拉默认 2rem；保留字号缩放和内容滚动。
- 文案仅保留必要标题、字段、操作、状态与错误，删除教程、重复提示和设计说明。状态含正常、悬停、按下、选中、禁用、焦点、加载与错误；颜色与图标辅助文字。

## 控制台结构与组件

主导航固定展开，宽约 13rem，分「工作区」与「管理」：节点总览、事件记录、通知管理；设置、管理员专属账号管理。节点总览是表格入口，打开节点后进入独立工作长页，面包屑返回总览；不再保留可拖宽目录与详情并排的旧工作区。

| 页面 | 信息与操作组织 |
|---|---|
| 节点总览 | 在线／登记、检测、推流与事件摘要 → 搜索／类型／在线筛选 → 节点表；主操作为打开节点，通知节点进入通知管理，浏览器相机入口归此页。 |
| 节点长页 | 来源与检测（发布端为来源与推流）→ 检测规则 → 设备与关联 → 维护与诊断；逐来源启停紧邻来源，全部来源控制独立；相机配置与推流同组。 |
| 事件记录 | 统一筛选在上，列表与所选事件证据并排；截图、节点来源、完整时间、检测结果、收件回执集中，详情可打开节点。 |
| 通知长页 | 选择通知节点；接收范围 → 报警与声音 → 音频库 → 设备与维护。未提供的能力不设空壳入口，离线范围仍可保存。 |
| 设置长页 | 账号与安全 → 本机与外观 → 服务与维护；本机名称、外观、服务时区和缓存各归所属职责。 |
| 账号管理长页 | 账号列表 → 创建账号 → 所选账号设置；表格操作定位本页表单，保留创建、权限、启禁用与密码重置。 |

- 二级菜单只滚动定位，所有当前对象设置连续展示，滚动同步高亮；不写“本页目录”等显然提示，不用 Tabs、折叠、侧栏或编辑弹窗拆分这些分组。危险确认及文件选择保留必要临时交互。
- 以 1600×1000、1280×800 两档 16:10 检查；页内定位约 9rem，正文使用剩余空间并限宽约 68rem。统一正文滚动链，定位菜单固定；页面内边距与分组间距 1.5rem，内容按职责分组，不多层嵌套卡片。
- 页面标题 24／32、分组标题按官方 CardTitle、正文 14／20。按钮、Input、NativeSelect 用 Nova 默认 2rem；采用官方尺寸变体，不用 padding 叠加出不同高度。同组标签、输入和操作分别对齐，表格操作间距 .5rem，长名称换行与详情滚动。
- 组合官方 Sidebar、Breadcrumb、Card、Table、FieldGroup／Field、Input、NativeSelect、ToggleGroup、Checkbox、Separator；反馈使用 Alert／Empty／Skeleton，确认使用 AlertDialog。只为业务布局与定位编写必要代码，不复制线框的示意控件样式。
- 全部功能继续接现有 API、权限与能力判断；逐项保存和规则草稿保留，切对象或离开前可保存、放弃或继续，保存离开等待执行完成。转发、成功、失败与结果待核实分别显示；不因点击而宣称成功。

## 原生界面布局

### Windows 视觉推理节点

WPF 保留主预览、紧凑来源列表和检查区。列表只显示名称、状态、帧率，完整信息进入来源详情的概览、采集与来源、检测规则、遮罩。规则与遮罩编辑独立草稿并提供离开保护；来源配置成功才入列、临时断流保留配置，画面等比留边。默认 1420×800 DIP、最小 720×480 DIP；两根分隔条分别调节来源与检查区，不足 1080 DIP 时检查区使用侧层，内容独立滚动。

全局设置按账号与设备、模型资源、外观、后台运行、版本与维护、运行方式、节点状态组织。节点级模式及绑定影响全部来源，独立于选中的来源；模型下载只有全局入口，来源规则提供跳转。长文字换行或显示完整提示，不强制一屏装完。现有容量、采样范围与检测链不变，详情见[Windows 节点](30-Windows视觉节点.md)。

### Android 视觉推理、相机与通知节点

Android 推理端主工作区保留预览、来源与关键异常；来源详情按概览、采集与来源、检测规则、遮罩组织，宽屏来源目录与详情并排、窄屏完整详情。规则用紧凑有界输入，遮罩宽屏画布与列表并排；不预设六页或固定高度。设置目录将节点状态与账号设备、模型资源、外观、后台权限、维护分开。草稿与离开保护、模型资源职责见[Android 节点界面](31-Android视觉推理节点.md#界面)。

相机主页面仅有控制 / 状态与预览两个区域：手机控制区占一半，平板占三分之一（可用短边至少 600dp，字号不超过 1.3），大字号控制区占一半。横屏左控制右预览，竖屏上预览下控制，区域间距 12dp；关闭预览只在原区域居中显示状态，尺寸和位置不变。正常场景主控件一屏容纳，极短窗口或超大字号保留控制区内滚动与固定启停。通知主页面为接警控制 / 最近报警双区：横屏左控制右记录，竖屏上控制下记录，手机各占一半，平板控制占三分之一（可用短边至少 600dp）；内距与区域间距均为 12dp。常规字号两区各自滚动，接警按钮固定在控制区底部；字号超过 1.3 或竖屏可用高度不足 440dp 时改为单列整页滚动。登录表单最大 480dp 居中，系统栏、安全区和键盘遵循平台。

相机控制区包含账号 / 帮助 / 设置的同尺寸图标入口、独立状态行、入队 / 服务收帧 / 两端丢弃三列统计、共用标签列的目标与规格、等宽规格按钮、等宽亮度 / 预览开关及底部固定启停。主控件触点至少 48dp，行间距统一按高度为 4dp / 12dp，宽松高度下控制组居中；预览开关采用开启语义。解释、完整状态 / 统计 / 来源、采集尺寸与主动未采样计数统一放帮助页；主界面保留实际发送尺寸 / 回退，不堆叠操作提示。预览区只呈现画面或居中状态。

通知顶部同样提供账号 / 帮助 / 设置 48dp 图标入口。两区标题最小高 48dp、水平内距 12dp，标题与状态 / 全部记录共用中心线；控制内容从顶部排列，接收范围与铃声的标签列为随字号缩放的 64dp，字段值和箭头各自对齐。常规控件间距 8dp、水平内距及按钮底部留白 12dp；控制区高度不足 320dp 时，内容间距缩至 4dp、按钮底部留白为 8dp，本次收件 / 服务响应移至帮助，保留 48dp 触点。控制区集中连接状态、重连、系统通知缺权限入口、接收范围、铃声、等宽循环次数 / 铃声库及接警启停；完整范围、连接地址、时间标准、连接统计和收件 / 播放说明在帮助弹窗中查看。最近报警默认最多六条，列表上下内距 4dp、记录上下内距 8dp，显示来源、时间与实际结束方式，并保留全部记录入口；大字号单列显示最近四条。历史、铃声库、录音 / 导入、重命名 / 删除确认复用返回标题、列表行、空状态和弹窗。共用账号、改名、改密与外观入口遵循同一尺寸。

通知告警确认用全屏目标展示：竖屏居中目标名称与位图，宽横屏左图右名称，系统安全区内距 24dp，超大字号保留内容滚动。人 / 汽车的透明 PNG 位于 `notifier/android/app/src/main/res/drawable-nodpi/`，由 imagegen 生成并保留原像素，作为目标示意而非事件画面；功能入口继续使用 Lucide。目标名称为主要文本，短名称 64sp，其他类别与连接中断等事件使用可换行标题。图像柔和浮现 420ms、扫描光带周期 3600ms，系统关闭动画时静态显示。全屏展示区轻点即可调用确认停止，底部仅提示操作；48dp 详情入口消费自身点击，不确认告警。详情另开普通弹窗，关闭返回未确认告警；确认错误始终可见，不替代保存结果。

## 本地预览与数据边界

控件有明确标签，密码默认遮罩；当前值与草稿分开，保存读取当前输入。危险操作先确认并默认取消，普通弹窗支持返回／Escape 及焦点恢复；活动报警仍只通过既有确认规则停止。空态、加载、离线、失败、权限与执行结果显示真实状态；缺值为“未报告”。

| 字段 | 当前合法范围 |
|---|---|
| 设备名、Windows 来源名、铃声展示名 | 非空，最多 64 个 UTF-16 单元，禁止 U+0000–U+001F；emoji 通常占 2 单元 |
| 生成名称的设备型号 | 最多 48 个 UTF-16 单元，去除控制字符；仅用于展示 |
| 自定义音频库 / 远程导入 | 最多 100 项；展示名最多 64 个 UTF-16 单元；MP3 / WAV / OGG / M4A，远程文件最多 512 KiB、60 秒 |
| 每视觉推理节点来源数 | 1–16；未报告来源可为空，不能据此伪造节点支持 0 路采集 |
| 来源置信度 / 冷却 / 采样率 | 10–95% / 整数 1–300 秒 / 整数 1–5 FPS |
| 来源异常短文 / 事件摘要 / 目标框数 | 最多 256 / 256 个 UTF-16 单元 / 100 个 |
| 目标集合 | 最多 256 项、每项 64、总长 4096 个 UTF-16 单元；至少选一项 |

名称按现有契约校验，不静默截断保存；合法长名称和错误可换行或滚动。数值校验范围、精度和有限性，来源运行时不可修改的规则保持只读。数据语义、权限及 API 契约不因布局调整变化。

本地 UI 检查走 scripts/ui-preview.ps1 的隔离服务，只有有数据场景显式启用 -MockData；模拟节点、截图及回执不证明真实检测、收件或声音。缓存只读复用 server/data/{models,releases}。真实链路与 UI、构建、设备和生产验证分开记录，入口见[构建验证与发布](60-构建验证与发布.md)。

## 图标

功能图标统一为官方 Lucide 1.49.0：Web 使用 lucide-react，原生端由同版 SVG 机械生成，不手绘或混用。图标随语义文字色，独立图标操作有准确名称；许可证随组件分发。node scripts/generate-lucide-icons.js --check 检查来源与输出，品牌素材见 [icon](../icon/README.md)。

## 实现与核验

- 控制台：receiver/web/src/components/ui/、components/theme-provider.tsx、ConsoleLayout.tsx 与各工作页，应用 CSS 只组织业务布局。
- 其他端：detector/web/src/style.css、WPF Themes/DarkTheme.xaml 与 Views/、共享 VisionGuardTheme.kt；Android 细则见[Android 界面规范](71-Android界面规范.md)。
- node scripts/check-ui-theme.js 在 CI 核对控制台官方主题、其他端现有主题、文字对比和资源引用。静态检查不替代实际窗口或设备目检；控制台布局验证仅限本轮实际检查的 16:10，不推断其他比例。
