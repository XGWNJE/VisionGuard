## 未完成事项

编号长期沿用，检索历史记录时按编号对应。排序口径：先按**是否卡住别人**，再按**影响面**（影响真实部署的排在锦上添花之前），最后看**性价比**（同样的价值里先做小而确定的）；同等条件下，"已经在跑但不准 / 不可信"排在"还没有但能用"之前。

### 高：能被立刻解决、且不解决就一直硌着

- [ ] **1. 正式链路的同轮端到端复核（GPU 走完下载→消费）**：本轮真机验证里，GPU 产物最后是用 `adb push` 放进应用目录的（下载路径另在设备上单独验过），**没在同一次会话里走「从服务端下载完成 → 由正式来源直接消费」**；CPU 正式档与多路并发也没在本轮真机复测。这是发布后唯一还没闭环的验收动作，成本低、结论直接决定 GPU 能不能放心上生产（见[验证记录](90-验证记录.md#0612-发布与真机全链路2026-10-11)的未覆盖段）。
- [ ] **2. 推理节点更新入口（客户端）**：发布侧已齐（平台表 + 发行资产 + `/api/update?platform=android-inference` 可下载），但应用里没有「检查更新 → 下载安装」，用户只能手动装包。范围含系统画面采集接入。做完才真正闭环「控制台看到更新 → 设备装上」。
- [ ] **3. 通知节点小米 15 锁屏漏收根因**：已修复底层网络恢复仍等 30 秒退避的问题，静音锁屏回归有收件证据，但**最初漏收的根因仍未确认**。这是唯一还开着的现场缺陷，影响的是“报警到底能不能送到”这类信任问题；见[专项记录](90-验证记录.md#节点改名web-会话与小米-15-静音锁屏专项2026-10-08)。

### 中：影响真实部署质量，但可以排期

- [ ] **5. 模型报告记录 GPU 厂商与驱动**：报告「设备」只到机型与 SoC，一旦接入 Qualcomm／别家 GPU，读数会混在一张表里无法归因。改动很小，趁现在只有一台设备时补最省事（跨平台结论见[优化专题](32-推理框架与模型优化.md#gpu-跨平台适配qualcomm-soc)）。
- [ ] **6. 校准集换成相机实拍**：量化校准仍借用照片夹具。当前质量读数够用，但真实镜头下的分布（夜视、逆光、抖动）与照片不同，会影响量化后分数上限；按[优化专题](32-推理框架与模型优化.md#量化现状2026-10-11)改用推流或本机采集。
