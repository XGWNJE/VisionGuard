- [ ] 完整量化产物与 GPU 复测（owner 已定计划，**等待开工指令**）：目标是 int8/uint8 输入输出的 TFLite，再把之前 GPU 全失败的 12 条组合（3 模型结构 × 4 配置：默认 / FP16 / 纹理权重+关外部张量 / 关外部张量）用新产物在真机重测。
  - 起因：现有 `.tflite` 的「INT8」不是整数图——实测 **QUANTIZE 0 次、DEQUANTIZE 378 次、DIV 379、ROUND 378，算子 3270 个**（FP32 版仅 421 个），是 float 图反复反量化，疑为 LiteRT 在 ARM 上慢 6 倍的根因。`onnx2tf` 严格全整数量化在解码段报 `Unsupported op ... ROUND`。
  - 步骤：① 装 `ai-edge-quantizer` 0.10.0（依赖 `ai-edge-litert==2.3.0`，会把本机 2.1.2 升级；装前 `pip freeze` 留回滚点，装后复跑三个 TFLite 脚本冒烟）；② 造产物，三条路径按成本试：quantizer 直接量化现有 TFLite（预计不通，10 分钟证伪）→ TF `TFLiteConverter` 全整数量化（需 `keras`，最可能成功）→ `ai_edge_torch` 走 StableHLO；③ 真机复测 12 条 GPU 组合 + NPU 一条；④ 结果入[验证记录](90-验证记录.md)。
  - **验收不能只看 I/O 类型**：必须是真整数图（QUANTIZE > 0 且 DIV/ROUND 大幅下降、算子数量回到几百量级），否则「接口变 int8 但图内仍是 float 骨架」，GPU 照样不吃。
  - 待 owner 定：复测组合范围确认、是否允许升级 litert 到 2.3.0、是否允许装 `keras`。真机执行需 owner 配合（本机 `adb devices` 为 0，我只能打包）。
