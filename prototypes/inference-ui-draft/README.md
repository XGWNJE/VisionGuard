# 推理节点 HTML 设计草稿 · 第五版

仅设计原型，不改 WPF / Android 生产代码，不连接真实设备，不创建 PR、不推送、不部署。

## 打开

下载交付包后直接打开 `VisionGuard-inference-draft.html`。所有脚本、样式和 Geist 字体已内联，离线运行；中文使用本机无衬线字体。顶部切换 Windows / Android、演示场景与深浅色。刷新会重置演示数据。

## 当前信息结构（第五版）

- **工作**：工作台与 Windows 性能检测。工作台顶部只有紧凑功能操作行，节点模式、所选来源启停、全部停止、Windows 推流目标刷新/选择/解绑集中在这里。
- **初始化**：模型、账号与设备、Windows 推理后端。左栏直接进入分类，删除原节点页二级分类标签。
- **运行维护**：Windows 连接、后台/权限、维护。Android 自动重连，不制造空的连接设置页。
- **统一状态区**：位于工作区，不在导航。控制连接、各来源状态和所选来源读数集中；节点明细折叠容纳媒体、服务、前台/驻留、权限等状态。来源列表只用于选择和类型辨认，不重复状态。
- **来源配置**：右侧保留规则/来源/隐私遮罩；Windows 推流态只显示来源配置，不把本机检测规则和遮罩当作推流有效配置。
- **项目品牌**：直接使用 `icon/visionguard-app.svg`，仅复制到原型 assets 以支持离线；不改变项目图形。标准按钮仍用仓库 shadcn 与 Lucide。
- **窄屏意图**：侧栏变为可横向滚动的文字导航分组，不依赖 hover；Android 操作保持44px触控尺寸。2:1、16:10 布局仍需真实浏览器验收。

## 第六版：模式目录与工作台平衡

- 推流目录、检索、可见数量、集中来源状态均使用 `visibleSources`，仅含本机窗口/屏幕；底层 `sources` 不删除远程配置、模型、规则或遮罩。切回推理恢复完整目录。服务总登记限额仍对完整目录计数，不能通过隐藏远程绕过容量。
- 选中远程时切推流，切换停止全部后选择首个本机来源，清理旧焦点/规则草稿/名称草稿/检索；未保存规则仍先确认。没有本机来源时不进入推流。移除最后本机来源后显示本机空态，允许切回推理找回远程。
- 推流“全部停止”仅作用于本机可见组；切换模式本身依旧停止全部节点来源，不自动恢复。
- 工作台从贯穿顶部的大状态条改为左侧画面 + 其下统一状态卡、右侧参数卡。预览最大宽560px，桌面内容双栏比例1.15:1；来源列184px，区域间距16px，字段/底栏边距一致。窄屏900px以下纵向排列，Android保留44px触控目标。状态只在该区域出现，不搬回菜单或重复到来源卡。
- 这属于用户要求的导航过滤/新布局设计，不声称原生已采用同样目录布局。未执行真实浏览器渲染；1600×800、1280×800视觉/溢出与触摸仍待验证，DOM不代替视觉验收。

## 第七版：来源指标与按需大屏预览

- 源项主体为原生可键盘激活按钮，仅打开该来源的大屏预览；旁侧唯一“设置”按钮选中来源参数。两者为兄弟按钮，无嵌套交互。预览使用独立 `previewId`，不切换所编辑来源，不丢失尚未保存规则。
- 移除常驻预览/隐藏按钮/放大按钮与集中来源状态条。每条来源的状态、实际FPS、最近成功帧推理耗时、实际后端、最近本地报警各只出现一次，按列对齐。节点控制连接、媒体和节点详情仍留在独立小区域，不与来源数据混合。来源面板340px；释放区域用于两列参数布局，窄屏改一列。
- 推流仍仅显示本机来源，源项使用目标FPS、服务收帧确认序列、丢帧。未知媒体状态不生成确认值。推流预览不绘检测框/遮罩。

- FPS采用来源实际采样值，不是目标配置；Android停止后归零，故障/无帧时标最后采样。耗时为最近成功帧engine.run耗时，不是全流程或平均；停止后显示上次耗时/后端。证据：Android SourceRuntime.kt164–171、300–314、341–348、368。所有数值仍明确是离线示例，未运行真实引擎。
